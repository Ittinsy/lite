LITE - HOW TO BUILD
===================

Lite is a small Electron app that creates and launches isolated browser
containers on top of the fingerprint-chromium kernel.


1. REQUIREMENTS
---------------
- Windows 10/11, x64
- Node.js (LTS) with npm
- Internet access for the first build (npm packages, the Electron runtime and
  the packager's helper tools are downloaded)
- Versions used for the last build: Electron 45.3.1, electron-builder 26.18.0


2. SOURCE FILES
---------------
main.js          main process: container storage, launching, stopping
preload.js       bridge between the window and the main process
index.html       user interface (Vue + Element Plus, loaded from node_modules)
verify.html      standalone fingerprint self-test page (not part of the build)
package.json     dependencies and build configuration
package-lock.json  exact dependency versions
howtobuild.txt   this file

Not part of the source: node_modules, dist, data, kernel.


3. FINGERPRINT KERNEL (NOT INCLUDED)
------------------------------------
Download the Windows build of fingerprint-chromium, version 148, from
  https://github.com/adryfish/fingerprint-chromium/releases
and extract it so that chrome.exe sits directly inside the "kernel" folder:

  kernel\chrome.exe
  kernel\...other kernel files

The build tested reports Chrome 148.0.7778.217. Kernel 150 was avoided because
of a Canvas fingerprint problem.


4. INSTALL DEPENDENCIES
-----------------------
In the source folder:

  npm install

vue and element-plus must stay under "dependencies" in package.json. They are
loaded by index.html from node_modules, and packages listed under
"devDependencies" are not included in the build.


5. RUN IN DEVELOPMENT
---------------------
  npm start

In development the app uses the PARENT folder of the source folder as its
root. For example, with the source in F:\lite\shell:

  F:\lite\kernel\chrome.exe
  F:\lite\data\          (created automatically)


6. BUILD
--------
Single portable file:

  npm run dist
  -> dist\lite.exe

  The portable exe unpacks the Electron runtime into a temporary folder on
  every launch, so startup takes a few seconds.

Unpacked folder (faster startup):

  npm run dist:dir
  -> dist\win-unpacked\lite.exe  (ship the whole folder)

Neither build is code-signed, so Windows SmartScreen or antivirus software may
show a warning. No application icon is set; the default Electron icon is used.


7. RELEASE LAYOUT
-----------------
Portable build:

  release\
    lite.exe
    kernel\chrome.exe ...
    verify.html            (optional)
    data\                  (created on first run)

Unpacked build: copy the contents of dist\win-unpacked into the release folder
and add the kernel folder next to lite.exe.

Do not ship a "data" folder from development.


8. DATA LAYOUT
--------------
  data\containers\<id>\config.json   settings of one container
  data\containers\<id>\profile\      the browser profile (user data)
  data\electron\                     the manager's own data

There is no central list. On every refresh the manager scans data\containers,
so a container whose folder was deleted simply disappears from the list.
Deleting a container in the UI stops its browser and deletes its folder.
Seeds are generated when a container is created and are kept when it is edited.


9. TESTING A BUILD
------------------
1. Start lite.exe: the container list must appear, with no kernel warning.
2. Create a container, press Start, and open verify.html in that browser.
3. Run verify.html in two containers and use "Report and comparison" to check
   which values differ between them.
